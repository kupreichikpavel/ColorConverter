# Image Info — чтение информации из графических файлов

Лабораторная работа №2. Приложение читает из графических файлов основные характеристики
изображения. Можно указать папку с любым количеством файлов (проверено на 100 000).

Форматы: **JPEG, GIF, TIFF, BMP, PNG, PCX**.

| Колонка | Откуда берётся |
|---|---|
| Имя файла | файловая система |
| Размер, px | заголовок формата (см. ниже) |
| Разрешение, dpi | BMP `biXPelsPerMeter`, PNG `pHYs`, JPEG JFIF/Exif, TIFF теги 282/283/296, PCX `HDpi/VDpi`; GIF не хранит |
| Глубина цвета | бит на пиксель |
| Сжатие | поле сжатия формата |
| Статус | OK / расширение не совпадает с содержимым / не изображение / заголовок не читается |

Дополнительно выводятся: размер палитры, тип цвета и метод фильтрации PNG, маркер SOF и
субдискретизация цветности JPEG, данные Exif (камера, дата, ориентация), кадры и повторы GIF,
версия и плоскости PCX и др. У каждой характеристики в программе есть пояснение: что это и
где хранится в файле.

## Запуск

```bash
./gradlew :lab2-image-info:run                         # графический интерфейс
./gradlew :lab2-image-info:run --args="D:/photos"      # сразу просканировать папку
./gradlew :lab2-image-info:test                        # тесты
./gradlew :lab2-image-info:run --args="--cli D:/photos --details"   # консольный режим
```

Windows-установщик `ImageInfo.exe` собирает GitHub Actions (workflow **Build Windows EXE**).

## Как достаются данные

| Что | Чем |
|---|---|
| Метаданные изображений | библиотека **metadata-extractor 2.19.0** (Drew Noakes, Apache 2.0) |
| Интерфейс и превью картинки | JavaFX 21 |
| Тесты | JUnit 5 |

### Как работает библиотека

1. `FileTypeDetector.detectFileType` читает первые байты и определяет формат по сигнатуре
   (magic number), а не по расширению: BMP — `BM`, PNG — `89 50 4E 47`, JPEG — `FF D8 FF`,
   GIF — `GIF8`, TIFF — `II*\0` / `MM\0*`, PCX — `0A`.
2. `ImageMetadataReader.readMetadata` вызывает читатель нужного формата. Он разбирает только
   заголовки, пиксели не декодируются:
   - JPEG — сегменты от `SOI` до начала сжатых данных `SOS` (`SOF`, `APP0 JFIF`, `APP1 Exif`, `DHT`);
   - PNG — чанки (`IHDR`, `PLTE`, `pHYs`, `gAMA`, `tRNS`…), данные `IDAT` пропускаются;
   - TIFF — каталог IFD с тегами;
   - BMP — `BITMAPFILEHEADER` + `BITMAPINFOHEADER`;
   - GIF — Logical Screen Descriptor и блоки кадров;
   - PCX — 128-байтовый заголовок.
3. Результат — набор «директорий» с тегами (`JpegDirectory`, `PngDirectory`, `ExifIFD0Directory`,
   `BmpHeaderDirectory`, `GifHeaderDirectory`, `PcxDirectory`…). Класс `reader/ImageInfoReader`
   берёт из них нужные значения и приводит к единому виду (размер, dpi, глубина, сжатие).

### Что вычисляется в программе (а не берётся из библиотеки готовым)

| Характеристика | Формула |
|---|---|
| dpi из пикселей на метр (BMP, PNG) | `ppm × 0.0254` |
| dpi из точек на сантиметр (JPEG, TIFF) | `dpcm × 2.54` |
| Глубина JPEG | точность × число компонент (8 × 3 = 24) |
| Глубина PNG | бит на канал × число каналов (тип 2 → 3, тип 4 → 2, тип 6 → 4, иначе 1) |
| Глубина TIFF | сумма BitsPerSample по всем каналам |
| Глубина PCX | бит на пиксель × число плоскостей |
| Глубина GIF | log₂(размер палитры) |
| Размер PCX | `Xmax − Xmin + 1` × `Ymax − Ymin + 1` |
| Субдискретизация JPEG | отношение коэффициентов H×V компоненты Y к Cb |
| Разрешение JPEG | JFIF, если в нём заданы единицы (1 — дюйм, 2 — см), иначе Exif |

### Особенности, найденные при проверке

- **GIF:** тег библиотеки `TAG_BITS_PER_PIXEL` — это поле *Color Resolution* заголовка, а не
  реальная глубина. Для файла с 16 цветами он даёт 8 бит. Поэтому глубина GIF считается по
  размеру палитры: 16 цветов → 4 бита.
- **TIFF:** обычный несжатый TIFF с порядком байтов Intel имеет ту же сигнатуру, что RAW-файлы
  Sony (ARW), и детектор библиотеки может принять его за ARW. Программа считает все TIFF-контейнеры
  (ARW, CR2, NEF, ORF, RW2) форматом TIFF и читает их как TIFF.
- **PCX:** читатель библиотеки принимает только файлы со сжатием RLE (байт кодирования = 1),
  поэтому сжатие PCX всегда «RLE».

## Быстродействие

- Читаются только заголовки: с JPEG размером 6,5 МБ библиотека читает около 70 КБ.
- Файлы обрабатываются пулом потоков (по умолчанию 2 × число ядер, настраивается в интерфейсе).
- Интерфейс не блокируется: результаты забираются из очереди пачками раз в 50 мс, таблица
  пересобирается не чаще раза в 150 мс, есть прогресс-бар и кнопка «Остановить».

| Папка | Время |
|---|---|
| 600 JPEG, 3,8 ГБ | 0,5–0,7 с |
| 100 000 файлов в 100 папках | 5 с |

Замеры на одном ядре при прогретом кэше диска; с холодного HDD время определяется скоростью диска.

## Интерфейс

- открыть папку (с подпапками или без) или отдельные файлы; перетащить файлы и папки в окно;
- таблица с сортировкой по любой колонке, имена — в «естественном» порядке (2 < 10);
- поиск по имени, фильтры по статусу и формату;
- панель деталей: превью, все характеристики с пояснениями;
- прогресс-бар, скорость, счётчики статусов, экспорт таблицы в CSV.

## Структура

```text
reader/    ImageInfoReader — чтение характеристик через metadata-extractor
model/     ImageInfo (результат), FileStatus, ImageFormat, Glossary (пояснения)
scan/      ScanJob — многопоточный обход папки
view/      MainView, ScanController, DetailsPane — интерфейс JavaFX
cli/       ConsoleScanner — консольный режим
```
